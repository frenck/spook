## No repairs showed up after installing

That can be good news: Spook only reports what it finds, and it may have found nothing.

Give it some time first. After :term[Home Assistant] starts, Spook waits until everything is up, and then spreads its first checks over a couple of minutes. A few wait ten minutes.

To see that Spook is running:

1. Go to **Settings** > **Devices & services**.
2. Select **Spook**.
3. Select the **Repairs** device. Its sensors count the issues in your :term[repairs dashboard]{to="repairs"}, ignored ones included.

::screenshot{name="device-repairs" alt="The Repairs device Spook adds, with its sensors that count the issues and its buttons to ignore or unignore all of them."}
The Repairs device. If it is there and counting, Spook is running.

::

Spook missing from **Devices & services**? Then it is installed but not set up. [Activate the integration](/installation#activating-the-spook-integration).

## A repair is wrong

It happens, and it is a bug.

- **Make it go away:** open the repair and select **Ignore**. Spook remembers that for those exact findings.
- **Tell us:** [report it](/support#im-sure-ive-found-a-bug), with the text of the repair and the part of the automation, script or dashboard it complains about.

Not sure if it is wrong? [Fix your first repair](/fix-your-first-repair) explains how to read one.

## A repair came back after I ignored it

Spook keeps your choice per finding. When the same automation later uses another thing that does not exist, the list in the repair got longer. That is news, so the repair comes back. Fix or ignore it again, and Spook remembers the new list too.

Two other ways it comes back:

- Someone selected **Unignore all** on the **Repairs** device, or an automation ran the **Repairs: Unignore all issues 👻** action.
- You run an old version of Spook. Older versions lost ignored repairs on a reload. [Update Spook](/updating).

Neither of those? Then [report it](/support#im-sure-ive-found-a-bug).

## An action is not in the list

1. In the action picker, search for 👻. Every :term[action] Spook adds carries one.
2. Check that the integration the action belongs to is set up. The actions for covers are only there when your Home Assistant has covers, for example. They appear the moment that integration is set up.
3. Installed through HACS and did not restart yet? Restart Home Assistant, then [activate Spook](/installation#activating-the-spook-integration).

::screenshot{name="actions-ghost-search" alt="The action picker, searched for the ghost, listing the actions Spook adds."}
Search for 👻, and Spook's actions are all there.

::

Still missing? Look it up in the [actions list](/actions). An action that is not on that page does not exist, or [moved into Home Assistant](/previous-features).

## Searching for 👻 finds no trigger or condition

Correct, they don't carry one. Only actions and helpers do.

Search for the trigger or condition by its name. The names are on the [triggers](/triggers) and [conditions](/conditions) pages.

## Spook stopped working after a Home Assistant update

That can happen. Spook uses parts of Home Assistant that are not meant for outsiders, and those change.

Update Spook, and check the issue tracker if there is no update. The steps are in [Updating Spook](/updating#after-a-home-assistant-update).

Often only one part of Spook is affected. A check that fails to start is skipped, the rest carries on, and the logs name the one that failed.

## Home Assistant feels slow since Spook

Spook does work: it reads your automations, scripts and dashboards. The heavier checks wait until Home Assistant has started, and run again when something changes.

To find out if it is Spook:

1. Go to **Settings** > **Devices & services** > **Spook**.
2. Open the menu of the :term[integration entry], and disable it. The integration entry is the row called **Your homie** on that page.

::screenshot{name="spook-entry-menu" alt="Spook's integration page, with the menu of the row called Your homie open, down to Download diagnostics, Disable and Delete."}
The menu of the row called **Your homie**. The other rows are Spook's devices.

::

3. Use Home Assistant for a while. Then enable it again the same way.

Faster without Spook? That is a bug, and we want to hear about it. [Report it](/support#im-sure-ive-found-a-bug), with the logs from below.

## Getting the logs

A bug report without logs is a guessing game.

**The logs.** Go to **Settings** > **System** > **Logs**, and search for `spook`.

**Debug logging**, for when the normal logs say nothing:

1. Go to **Settings** > **Devices & services** > **Spook**.
2. Turn on debug logging from the menu on that page.
3. Do the thing that goes wrong.
4. Turn debug logging off again. Home Assistant then offers the log as a download.

Prefer YAML? This does the same, after a restart:

```yaml
logger:
  logs:
    custom_components.spook: debug
```

**Diagnostics.** The same page offers a diagnostics download for Spook. It lists the kinds of repairs Spook raised and the state of its helpers, without the names of your entities or automations. Add it to your report.

::warning
Read a log before you post it in public. Logs can hold names, addresses and other things about your home.

::
