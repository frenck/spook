The schedule :term[helper] in :term[Home Assistant] is on during the time blocks you give it for each day of the week, and off the rest of the time. Heating that follows the working week, for example.

Home Assistant lets you make and change a schedule on the helpers page, by hand. Spook adds actions for it, so an automation or a script can do the same: make a schedule, change the blocks of a day, and delete it again.

## Actions

Spook adds three actions for schedules. You find them wherever you add an action, marked with a 👻.

### Create a schedule

Creates a new schedule helper, the same as adding one on the helpers page.

Handy for a script or a blueprint that needs a week of time blocks to work with. Instead of telling people "first go make a schedule called this, with these blocks", it makes the schedule itself. The new schedule is an ordinary one: it shows up on the helpers page, and you can change it there like any other.

**How to use it**

1. Open the automation or script that should make the schedule, and select **Add action**.
2. Search for **create a schedule**, and select **Schedule: Create a schedule 👻**.
3. Fill in the **Name** of the new schedule.
4. For each day it should be on, fill in that day, like **Monday**, with its time blocks. Leave the days it should be off empty.
5. Optionally, set the **Schedule entity ID** and the **Icon**.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=schedule.create) opens it in your Home Assistant, ready to run once.

| **Action data parameters**                                                   |               |              |                                            |
| ---------------------------------------------------------------------------- | ------------- | ------------ | ------------------------------------------ |
| **Attribute**                                                                | **Type**      | **Required** | **Default / Example**                      |
| `name`                                                                       | :term[string] | Yes          | `Heating`                                  |
| `schedule_id`                                                                | :term[string] | No           | `heating`                                  |
| `icon`                                                                       | :term[string] | No           | `mdi:radiator`                             |
| `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, `sunday` | :term[list]   | No           | `[{"from": "07:00:00", "to": "09:00:00"}]` |

Each day takes a list of time blocks. A block has a `from` and a `to` time, and optionally `data`: values the schedule shows as attributes while that block is on. A `to` of `24:00:00` runs until midnight. Blocks on the same day cannot overlap, and each has to end after it starts; a schedule that breaks either is refused before anything is made. A day left out is off all day.

Without a `schedule_id`, the entity ID follows the name, as it does in the UI, and gets a number at the end if that name is already taken. With a `schedule_id`, you get exactly that entity ID or an error: one that is already taken is refused, and does not get a number at the end.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Heating on weekday mornings and evenings, and all of Saturday from nine:

```yaml
action: schedule.create
data:
  name: "Heating"
  schedule_id: heating
  monday:
    - from: "06:30:00"
      to: "08:30:00"
      data:
        temperature: 21
    - from: "17:00:00"
      to: "22:00:00"
  saturday:
    - from: "09:00:00"
      to: "24:00:00"
response_variable: created
```

The new schedule's entity ID is then in `{{ created.entity_id }}`.

### Delete a schedule

Deletes one or more schedule helpers.

The other half of [Create a schedule](#create-a-schedule). A script that made a schedule for itself can clean it up again once it is done, so the helpers page only has schedules you actually use.

**How to use it**

1. Open the automation or script that should do the deleting, and select **Add action**.
2. Search for **delete a schedule**, and select **Schedule: Delete a schedule 👻**.
3. Under **Entity ID**, pick the schedules to delete.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=schedule.delete) opens it in your Home Assistant, ready to run once. Mind that it really deletes.

### Set the time blocks of a day

Replaces the time blocks of one or more days of a schedule. The other days stay as they are.

Changing a schedule normally means opening its dialog and dragging blocks around. With this action, an automation does it for you. Clear the weekdays of the heating schedule when you leave for a holiday, and put them back the day before you return. Or let a dashboard button move the morning block when you have to be up early tomorrow.

**How to use it**

1. Open the automation or script that should change the schedule, and select **Add action**.
2. Search for **set the time blocks**, and select **Schedule: Set the time blocks of a day 👻**.
3. Under **Targets**, pick the schedule to change.
4. Under **Day**, pick the day, or several days, to change.
5. Fill in the **Time blocks** those days should have. An empty list leaves them off all day.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=schedule.set_day) opens it in your Home Assistant, ready to run once.

| **Action data parameters** |                                                    |              |                                            |
| -------------------------- | -------------------------------------------------- | ------------ | ------------------------------------------ |
| **Attribute**              | **Type**                                           | **Required** | **Default / Example**                      |
| `day`                      | :term[string] \| :term[list of strings]{to="list"} | Yes          | `saturday`                                 |
| `blocks`                   | :term[list]                                        | Yes          | `[{"from": "07:00:00", "to": "09:00:00"}]` |

A day is one of `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, or `sunday`. Give a list to set several days to the same blocks at once.

A block has a `from` and a `to` time, and optionally `data`: values the schedule shows as attributes while that block is on. A `to` of `24:00:00` runs until midnight. Blocks cannot overlap, and each has to end after it starts. Home Assistant checks them the same way its dialog does; blocks it refuses come back as an error, and nothing is changed.

An empty list of blocks leaves the days off all day.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

The weekend: a morning and an evening block, the morning one with a temperature:

```yaml
action: schedule.set_day
target:
  entity_id: schedule.heating
data:
  day:
    - saturday
    - sunday
  blocks:
    - from: "08:00:00"
      to: "12:00:00"
      data:
        temperature: 21
    - from: "17:00:00"
      to: "23:00:00"
```

A Friday off, all day:

```yaml
action: schedule.set_day
target:
  entity_id: schedule.heating
data:
  day: friday
  blocks: []
```

:::

:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Only schedules made in the UI can be changed. A schedule set up in YAML is refused, and can only be changed in the YAML.
- Changing how a schedule is set up is for admins, the same as in its dialog. An automation or a script can still use it.

:::
::

## Use cases

What people use this for:

- Let a script or a blueprint make the schedule it needs, with its whole week of time blocks, without a trip to the helpers page.
- Clean up schedules that are no longer needed from a script, so the helpers page only has schedules you actually use.
- Clear the weekdays of a heating schedule when you leave for a holiday, and put them back when you return.
- Let a script or a dashboard button move the morning block, without opening the schedule's dialog.
