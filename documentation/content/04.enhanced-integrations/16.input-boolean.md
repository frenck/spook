The input boolean :term[helper] in :term[Home Assistant] is a toggle: on or off, controlled from a dashboard or from :term[automations]{to="automation"}, and usable as a trigger or condition.

Spook adds actions to the input boolean :term[integration] to create and delete these helpers from automations and scripts.

## Actions

Spook adds two actions for input booleans. You find them wherever you add an action, marked with a 👻.

### Create an input boolean

Creates a new input boolean (toggle) helper, the same as adding one on the helpers page.

Some flags are only needed for a while. A script that runs a party mode, a move, a holiday: it needs a toggle to remember "this is going on", and nothing else ever looks at it. Made by hand, that toggle stays on the helpers page forever. Made with this action, the script makes it when it starts, and [deletes it](#delete-an-input-boolean) when it is done.

**How to use it**

1. Open the automation or script that should make the toggle, and select **Add action**.
2. Search for **create an input boolean**, and select **Input boolean: Create an input boolean 👻**.
3. Fill in **Name**, like `Guest mode`.
4. Optionally, set **Input boolean entity ID** to pick the entity ID yourself, **Initial value**, and **Icon**.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=input_boolean.create) opens it in your Home Assistant, ready to run once.

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Make a guest mode toggle, and keep its entity ID for the steps after it:

```yaml
action: input_boolean.create
data:
  name: "Guest mode"
  input_boolean_id: guest_mode
  initial: false
response_variable: created
```

The new input boolean's entity ID is then in `{{ created.entity_id }}`.

### Delete an input boolean

Deletes one or more input boolean helpers.

The other half of [Create an input boolean](#create-an-input-boolean): the script that made a toggle cleans it up again. It works on any input boolean made in the UI as well, disabled ones included.

**How to use it**

1. Open the automation or script that should do the cleaning up, and select **Add action**.
2. Search for **delete an input boolean**, and select **Input boolean: Delete an input boolean 👻**.
3. Under **Entity ID**, choose the input booleans to delete.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=input_boolean.delete) opens it in your Home Assistant, ready to run once. Mind that it really deletes.

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Remove the guest mode toggle again:

```yaml
action: input_boolean.delete

```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Input booleans set up in YAML can only be removed from the YAML. Asking for one is an error.
- Everything in the list is checked first: if one of them cannot be deleted, none of them are.

:::

## Use cases

What people use this for:

- Let a script make the flag it needs, and clean it up again afterwards, so the helpers page only has toggles you actually use.
