The input datetime :term[helper] in :term[Home Assistant] holds a date, a time, or both, that can be set from a dashboard or from :term[automations]{to="automation"}, and used as a trigger. An alarm clock you can put on a dashboard, for example.

Spook adds actions to the input datetime :term[integration] to create and delete these helpers from automations and scripts.

## Actions

Spook adds two actions for input datetimes. You find them wherever you add an action, marked with a 👻.

### Create an input datetime

Creates a new input datetime helper, the same as adding one on the helpers page.

Some moments only matter for a while. The time the guests are due, the day the holiday ends, the moment a script should check back. Made by hand, that helper stays on the helpers page long after. Made with this action, the script makes it when it needs it, and [deletes it](#delete-an-input-datetime) when it is done.

**How to use it**

1. Open the automation or script that should make the helper, and select **Add action**.
2. Search for **create an input datetime**, and select **Input datetime: Create an input datetime 👻**.
3. Fill in **Name**, like `Wake up`.
4. Turn on **Has a date**, **Has a time**, or both. At least one has to be on.
5. Optionally, set **Input datetime entity ID** to pick the entity ID yourself, **Initial value**, and **Icon**.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=input_datetime.create) opens it in your Home Assistant, ready to run once.

| **Action data parameters** |                |              |                       |
| -------------------------- | -------------- | ------------ | --------------------- |
| **Attribute**              | **Type**       | **Required** | **Default / Example** |
| `name`                     | :term[string]  | Yes          | `Wake up`             |
| `input_datetime_id`        | :term[string]  | No           | `wake_up`             |
| `has_date`                 | :term[boolean] | No           | `false`               |
| `has_time`                 | :term[boolean] | No           | `true`                |
| `initial`                  | :term[string]  | No           | `07:30:00`            |
| `icon`                     | :term[string]  | No           | `mdi:alarm`           |

At least one of `has_date` and `has_time` has to be on, and both are off when left out, so give at least one. An initial value has to be something Home Assistant can read as a date, a time, or both. One it cannot read is refused before anything is made.

Without an `input_datetime_id`, the entity ID follows the name, as it does in the UI, and gets a number at the end if that name is already taken. With an `input_datetime_id`, you get exactly that entity ID or an error: one that is already taken is refused, and does not get a number at the end.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Make a wake up time, set to half past seven, and keep its entity ID for the steps after it:

```yaml
action: input_datetime.create
data:
  name: "Wake up"
  input_datetime_id: wake_up
  has_time: true
  initial: "07:30:00"
response_variable: created
```

The new input datetime's entity ID is then in `{{ created.entity_id }}`.

### Delete an input datetime

Deletes one or more input datetime helpers.

The other half of [Create an input datetime](#create-an-input-datetime): the script that made a helper cleans it up again. It works on any input datetime made in the UI as well, disabled ones included.

**How to use it**

1. Open the automation or script that should do the cleaning up, and select **Add action**.
2. Search for **delete an input datetime**, and select **Input datetime: Delete an input datetime 👻**.
3. Under **Entity ID**, choose the input datetimes to delete.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=input_datetime.delete) opens it in your Home Assistant, ready to run once. Mind that it really deletes.

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Remove the wake up time again:

```yaml
action: input_datetime.delete

```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Input datetimes set up in YAML can only be removed from the YAML. Asking for one is an error.
- Everything in the list is checked first: if one of them cannot be deleted, none of them are.

:::

## Use cases

What people use this for:

- Let a script make the date or time it needs, and clean it up again afterwards, so the helpers page only has input datetimes you actually use.
