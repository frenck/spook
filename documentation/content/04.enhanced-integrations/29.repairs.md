The :term[repairs] :term[integration] brings the repairs dashboard into :term[Home Assistant]. It tells you about issues found in your Home Assistant instance. Other integrations (like Spook 👻 itself) raise these issues, so you can keep your system in working order.

An issue is only raised when it applies to your system, so what you see is relevant to you.

Spook adds actions to raise and manage your own repair issues, and entities that keep count of them.

::screenshot{name="actions-search-repairs" alt="The Add action dialog, searched for repair, with the actions Spook adds marked with a ghost."}
Spook adds many new actions to the repairs integration so that you can create your own.

::

## Devices & entities

Spook adds a **Repairs** device, with buttons to ignore or unignore every issue at once, sensors that count the issues, and an event entity that fires whenever an issue comes, changes or goes. Put the count on a dashboard, or trigger an automation the moment something new shows up in the repairs dashboard.

You find the device under **Settings** > **Devices & services**, on the Spook integration.

::screenshot{name="device-repairs" alt="The new Repairs device and its entities in the Home Assistant UI."}

::

### Buttons

#### Ignore all

Ignores every issue currently raised in the repairs dashboard, in one press.

_Default :term[entity ID]: `button.ignore_all_issues`_

::tip
Ignoring an issue does not solve it. It is better to fix the issue, remove the integration that causes it, or report a bug.

Every issue raised by Home Assistant (and Spook) should be solvable. If not, that is a bug, so please report it.

::

#### Unignore all

Brings back every issue you ignored that is still there, in one press.

_Default :term[entity ID]: `button.unignore_all_issues`_

### Events

#### Repair

Fires when a repair issue is raised, updated or removed. Use it as the trigger of an automation that tells you about a new issue right away, not when you happen to open the repairs dashboard.

_Default :term[entity ID]: `event.repair`_

The event type is `create`, `update` or `remove`, and the event also carries the integration that raised the issue and its issue ID.

### Sensors

#### Active issues

The number of issues in the repairs dashboard that you did not ignore. The one to watch.

_Default :term[entity ID]: `sensor.active_issues`_

#### Ignored issues

The number of issues that are still there, but that you ignored.

_Default :term[entity ID]: `sensor.ignored_issues`_

#### Total issues

The number of issues that are still there, ignored or not.

_Default :term[entity ID]: `sensor.issues`_

## Actions

Spook adds five actions for repairs. You find them wherever you add an action, marked with a 👻.

### Create issue

Raises an issue of your own in the repairs dashboard.

The repairs dashboard is where Home Assistant tells you something needs your attention. Your own automations have things to say too: a battery that is almost empty, a freezer that is warming up, a device that has not reported in for a day. A notification gets swiped away. An issue stays in the repairs dashboard until it is solved.

**How to use it**

1. Open the automation or script that should raise the issue, and select **Add action**.
2. Search for **create issue**, and select **Repairs: Create issue 👻**.
3. Fill in **Title** and **Description**. The description can use Markdown.
4. Optionally, set **Issue ID**, so you can update or [remove](#remove-issue) this issue later. Without it, every run raises a new issue.
5. Optionally, set **Severity**, **Domain** for the logo next to the issue, and turn on **Persistent** to keep the issue past a restart.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=repairs.create) opens it in your Home Assistant, ready to run once.

Raise a low battery issue, with an ID so it can be removed again once the battery is swapped:

```yaml
action: repairs.create
data:
  title: "Low battery"
  description: |-
    Found a low battery in your home. The following device is low on energy:

    The bed vertical movement sensor.
  issue_id: "low-battery"
```

### Ignore all issues

Ignores every issue currently raised in the repairs dashboard, or only the ones particular integrations raised.

Sometimes an integration raises an issue you know about and cannot act on yet, or the Marketplace asks for a restart after every update. This clears the dashboard in one step, for everything or for the integrations you name.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **ignore all issues**, and select **Repairs: Ignore all issues 👻**.
3. Optionally, set **Domain** to only ignore the issues of those integrations. Leave it empty for all of them.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=repairs.ignore_all) opens it in your Home Assistant, ready to run once.

::tip
Ignoring an issue does not solve it. It is better to fix the issue, remove the integration that causes it, or report a bug.

Every issue raised by Home Assistant (and Spook) should be solvable. If not, that is a bug, so please report it.

### List issues

Lists the issues currently raised in the repairs dashboard, with the same titles the dashboard shows them with, in the language Home Assistant is set to.

The repairs dashboard is only seen by whoever opens it. With this action, an automation can read it for you: send a summary every morning of what still needs fixing, show the open issues on a dashboard of your own, or only bother you about the critical ones.

**How to use it**

1. Open the automation or script that should read the issues, and select **Add action**.
2. Search for **list issues**, and select **Repairs: List issues 👻**.
3. Optionally, narrow it down with **Domain** and **Severity**, and turn on **Include ignored** to get the ignored issues as well.
4. Store the response in a variable, so the steps after it can use it.
5. Select **Save**.

The newest issue comes first. Ignored issues are left out, like on the repairs dashboard, unless you ask for them.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=repairs.list) opens it in your Home Assistant, ready to run once.

| -------------------------- | -------------------------------------------------- | ------------ | --------------------- |
| **Attribute**              | **Type**                                           | **Required** | **Default / Example** |
| `include_ignored`          | :term[boolean]                                     | No           | `false`               |
| `domain`                   | :term[string] \| :term[list of strings]{to="list"} | No           | `hue`                 |

Each issue in the response has its `domain`, `issue_id`, `title`, `severity` (`critical`, `error`, or `warning`), `created`, `is_fixable`, `learn_more_url`, `breaks_in_ha_version`, and whether it is `ignored`.

Issues made with `repairs.create` come back a little different. Their `issue_id` carries the `user_` prefix that `repairs.create` adds, so drop one `user_` before handing a listed ID to `repairs.remove` or `repairs.create`. And their `domain` is always `spook`, whatever `domain` they were created with, so filter on `spook` (or leave `domain` out) to find them.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Only the critical issues and errors, kept in a variable:

```yaml
action: repairs.list
data:
  severity:
    - critical
    - error
response_variable: repairs
```

The titles are then in `{{ repairs.issues | map(attribute='title') | list }}`.

:::

- Listing issues takes an admin, the same as the repairs dashboard does.

### Remove issue

Removes an issue you raised with [Create issue](#create-issue).

The battery is swapped, the freezer is cold again, the device reported back in. The automation that raised the issue, or another one, takes it away again, so the repairs dashboard only shows what still needs you.

**How to use it**

1. Open the automation or script that should remove the issue, and select **Add action**.
2. Search for **remove issue**, and select **Repairs: Remove issue 👻**.
3. Fill in **Issue ID**, the same one you gave when you created it.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=repairs.remove) opens it in your Home Assistant, ready to run once.

## Use cases

What people use this for:

- Raise your own issues: when a device is low on battery, offline for a long time, or not responding to commands. Remove them again once it is sorted.
- Show the open repairs on a dashboard of your own, or send yourself a daily summary of what still needs fixing.
