The trend :term[helper] tells you which way a value is going. It follows a source entity, like a temperature sensor, and turns on when the value rises (or falls, if you ask it to). Handy for "the bathroom humidity is climbing, somebody is showering, start the fan".

A trend helper only works as long as the entity it follows exists. Spook tells you when it does not.

## Repairs

Spook looks through your trend helpers for a source entity that no longer exists, and tells you in the :term[repairs dashboard]{to="repairs"}. New to repairs? Follow [Fix your first repair](/fix-your-first-repair).

### Unknown source entity

A trend helper follows an entity that no longer exists, usually because it was removed or replaced. The helper has nothing to follow, so it never changes.

**How to fix it:** Open the repair, and Spook offers to remove the helper for you, once Home Assistant deleted the entity it is missing. One that may just not be there yet, like one of an integration that is still starting up, gets no button. A trend helper cannot be pointed at another entity afterwards, so for a sensor that was replaced: remove this helper, and make a new one for the new sensor on the **Helpers** page, under **Settings** > **Devices & services**. Or bring back the entity that went missing. The repair disappears by itself once it is fixed.

::accordion
:::accordion-item{label="How Spook checks this" icon="i-mdi-magnify"}

Spook reads the configuration of every trend helper made in the UI, and raises a repair when the source entity it follows is unknown to Home Assistant. The repair names the trend helper and the missing source entity.

Spook reads the configuration, not the running entity. So a helper that failed to set up entirely is still checked, and that is the one most likely to be broken. Trend sensors set up in YAML are not checked.

This is one check, shared by every helper built on another entity. The [Home Assistant page](/homeassistant#unknown-helper-sources) explains it in full.
