The to-do list :term[integration] brings shopping lists and to-do lists into :term[Home Assistant]: the local one, the shopping list, and those of other services.

Reordering a list means dragging an item in the interface. That is the only way. Spook adds the action, so an automation can put the most urgent thing at the top.

## Actions

Spook adds one action for to-do lists. You find it wherever you add an action, marked with a 👻.

### Move item

Moves an item in a to-do list to the top, the bottom, or after another item.

Only you could change the order of a list, by dragging. Now an automation can too. Rain is coming tomorrow morning: the bins go to the top of the chores. The milk ran out: it moves up the shopping list, before you walk past the shop.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **move item**, and select **To-do list: Move item 👻**.
3. Under **Targets**, pick the to-do list.
4. Fill in the **Item** to move, by its name.
5. Either set **Position** to **Top** or **Bottom**, or fill in **After** with the item it should go after.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=todo.move_item) opens it in your Home Assistant, ready to run once.

| -------------------------- | ------------- | -------------------------- | --------------------- |
| **Attribute**              | **Type**      | **Required**               | **Default / Example** |
| `item`                     | :term[string] | Yes                        | Take out the bins     |
| `after`                    | :term[string] | No, but this or `position` | Do the dishes         |
| `position`                 | :term[string] | No, but this or `after`    | `top` or `bottom`     |

The item, and the item to put it after, are found by their title or their uid, the same way `todo.update_item` finds an item.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Rain is coming, so the bins go first:

```yaml
action: todo.move_item
target:
  entity_id: todo.chores
data:
  item: Take out the bins
  position: top
```

:::

:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Only lists that can be reordered can be targeted. Some lists keep their items in an order of their own, like one sorted by due date.
- An item that is not in the list, or a place after an item that is not, is an error, the same as for `todo.update_item`. So is moving an item after itself.

:::
