The calendar :term[integration] brings calendars into :term[Home Assistant]: a local calendar, CalDAV, Google Calendar, and more.

An automation can put an event in a calendar with `calendar.create_event`, and that is where it ends. Calendars that can delete an event do so only when asked from the calendar panel. Spook adds the actions to change an event, and to take it out again.

Spook finds events the way an automation can: by their title, in a stretch of time. No need to know an event's hidden identifier first.

## Actions

Spook adds two actions for calendars. You find them wherever you add an action, marked with a 👻.

### Delete event

Deletes events from a calendar, found by their title in a stretch of time.

An automation can put an event in a calendar, and Home Assistant leaves it at that. The reminder to take the bins out stays there after the bins went out, and the "guests arriving" event stays after the visit got cancelled. This action lets the automation clean up after itself.

When nothing matches, nothing happens. That is on purpose: "delete it if it is there" is what an automation tidying up needs.

**How to use it**

1. Open the automation or script that should delete the event, and select **Add action**.
2. Search for **delete event**, and select **Calendar: Delete event 👻**.
3. Under **Targets**, choose the calendar.
4. Fill in **Summary** with the title of the event, exactly as it is in the calendar.
5. Set **Duration** to how far ahead to look, like 24 hours. Spook looks from now, unless you set **Start date and time**.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=calendar.delete_event) opens it in your Home Assistant, ready to run once.

| -------------------------- | -------------- | ------------------------------- | --------------------- |

| `summary`                  | :term[string]  | No, but this or `uid`           | Dentist               |
| `uid`                      | :term[string]  | No, but this or `summary`       |                       |
| `start_date_time`          | datetime       | No                              | Now                   |
| `end_date_time`            | datetime       | No, but this or `duration`      | 2026-10-04 20:00:00   |
| `duration`                 | time period    | No, but this or `end_date_time` | `{"hours": 24}`       |
| `whole_series`             | :term[boolean] | No                              | `false`               |

Calendars delete an event by its uid, an identifier every event has, and `calendar.get_events` leaves that out of what it returns. That is why Spook finds events by their title instead, or by a `uid` when you do have one.

Events are looked for from `start_date_time`, which is now when you leave it out, until `end_date_time` or for `duration`, the same way `calendar.get_events` reads them. Every event in that stretch with exactly that `summary`, or that `uid`, or both, is deleted.

An event that repeats is found occurrence by occurrence, and only the occurrences found are deleted. Set `whole_series` to delete the whole series instead.

The response lists every event deleted, for each calendar, with its `uid`, `recurrence_id`, `summary`, `start` and `end`.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Take out the reminder an automation put in earlier today:

```yaml
action: calendar.delete_event
target:
  entity_id: calendar.family
data:
  summary: Take the bins out
  duration:
    hours: 24
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- A `summary` or a `uid` is required. A stretch of time alone would delete everything in it. That is how a calendar gets emptied by accident.
- The title has to match exactly, including capitals.
- Only calendars that can delete events can be targeted. A read-only calendar, like a holiday feed, refuses the action.
- An event the calendar gives no uid cannot be told apart from any other, so it is left alone.

:::
::

### Update event

Changes events in a calendar, found by their title in a stretch of time: a new title, a new place, or new times.

Plans move. The dentist runs late, or the barbecue gets pushed back an hour because of rain. An automation that knows can now change the event, so you do not have to open the calendar app.

**How to use it**

1. Open the automation or script that should change the event, and select **Add action**.
2. Search for **update event**, and select **Calendar: Update event 👻**.
3. Under **Targets**, choose the calendar.
4. Fill in **Summary** with the title of the event, exactly as it is in the calendar, and set **Duration** to how far ahead to look.
5. Fill in what should change: a **New summary**, a **Description**, a **Location**, a **New start** or **New end**, or a **Shift** to move it later (or earlier, with a negative time).
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=calendar.update_event) opens it in your Home Assistant, ready to run once.

Events are found exactly the way [delete event](#delete-event) finds them. Every event found gets the changes you ask for, and keeps everything else it had: Home Assistant hands the calendar a whole event to update, so Spook carries over what you did not change.

To move an event, give it a `new_start`, and it keeps its length, or a `new_start` and a `new_end`, or a `new_end` alone to make it longer or shorter. Or move it by a `shift`, later, or earlier when negative. A time written without a time zone is read as Home Assistant's own.

The response lists every event changed, for each calendar, with its `uid` and its new `summary`, `start` and `end`.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

The dentist runs late again, so move today's appointment an hour on:

```yaml
action: calendar.update_event
target:
  entity_id: calendar.family
data:
  summary: Dentist
  duration:
    hours: 24
  shift:
    hours: 1
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Something to change is required: a new summary, description, location, or new times.
- A `shift` together with a new start or end is refused. Say how to move an event one way.
- An event that lasts whole days moves by whole days only. Shifting it by an hour is refused, so you know it did not move.
- An event of a repeating series is changed on its own, never the whole series. Changing a series means changing its first event, and the times of whichever occurrence was found would move the series start along with them.
- Only calendars that can change events can be targeted. A read-only calendar, like a holiday feed, refuses the action.
- An event the calendar gives no uid cannot be told apart from any other, so it is left alone.

:::
