The sensor :term[integration] is the one that reports things: temperatures, power usage, how full the bins are. Most :term[integrations]{to="integration"} you install bring some along.

Home Assistant lets you set how many decimals a sensor shows, but one sensor at a time, in its settings. Fine for one. Less fine when an integration hands you forty power sensors that all report six decimals.

## Actions

Spook adds one action for sensors. You find it wherever you add an action, marked with a 👻.

### Set display precision

Sets the number of decimals shown for one or more sensors.

The same setting you find under **Display precision** in the settings of a sensor, for as many sensors as you like in one go. Trim everything an integration added down to one decimal. Or show a few more on one sensor while you work out why a reading looks off, and set it back afterwards.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **display precision**, and select **Sensor: Set display precision 👻**.
3. Under **Entity**, pick the sensors.
4. Set **Display precision** to the number of decimals, like `1`.
5. Select **Save**.

A one-off tidy-up does not need an automation at all: the link below runs it once.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=sensor.set_display_precision) opens it in your Home Assistant, ready to run once.

| **Action data parameters** |                              |              |                                    |
| -------------------------- | ---------------------------- | ------------ | ---------------------------------- |
| **Attribute**              | **Type**                     | **Required** | **Default / Example**              |
| `entity_id`                | :term[string] or :term[list] | Yes          | `"sensor.living_room_temperature"` |
| `display_precision`        | :term[integer]               | Yes          | `1`                                |

This is the same setting you find under a sensor's own settings in the UI, so it survives restarts and applies everywhere the sensor is shown.

Every entity you name is looked up before any of them are changed. If one of them does not exist, the whole call fails and nothing is touched. You do not end up with half your sensors updated.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

One decimal for both temperatures:

```yaml
action: sensor.set_display_precision
data:
  entity_id:
    - sensor.living_room_temperature
    - sensor.bedroom_temperature
  display_precision: 1
```

:::

:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- Only sensors with a unique ID can be changed, the same ones that have settings in the UI. A sensor without one is an error.
- Changing a sensor's settings is for admins, the same as in the UI. An automation or a script can still use it.

:::
::

## Use cases

What people use this for:

- Trim every sensor an integration added down to a sensible number of decimals in one action, instead of opening each one in the UI.
- Show more decimals on a sensor temporarily, for example while working out why a reading looks wrong, and set it back afterwards.
