Categories in :term[Home Assistant] sort your :term[automations]{to="automation"}, :term[scripts]{to="script"}, scenes, and :term[helpers]{to="helper"} into groups on their own pages in the user interface. Each of those pages has its own set of categories, and something sits in one category per page.

Home Assistant lets you file things by hand, one at a time. Spook adds actions so your own automations and scripts can do it: file new automations away automatically, or tidy up a page full of them in one go.

## Actions

Spook adds five actions for categories. You find them wherever you add an action, marked with a 👻. They all belong to the Home Assistant Core Integration, so that is the name in front of them in the list.

Run by hand, these actions need a user that is an administrator. Your automations and scripts can always run them.

::tip
**Categories by name**

Home Assistant never shows you the ID of a category, and it is a random one. So wherever an action below asks for a category, you type its name, like `Lighting`. Uppercase or lowercase does not matter.

::

### Create a category

Adds a new category to one of the pages: automations, scripts, scenes, or helpers.

Useful in a setup script that prepares the categories your other automations file things into, so they exist before anything needs them.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **create a category**, and select **Home Assistant Core Integration: Create a category 👻**.
3. Under **Scope**, pick the page the category is for: **Automations**, **Helpers**, **Scenes**, or **Scripts**.
4. Give it a **Name**, like `Lighting`, and pick an **Icon** if you like.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.create_category) opens it in your Home Assistant, ready to run once.

```yaml
  scope: automation
  name: Lighting
  icon: mdi:lightbulb
response_variable: category
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- A name another category on the same page already has is refused. The same name on a different page is fine.

### Update a category

Changes the name or icon of a category that already exists.

Deleting a category and creating it again would take it off everything that was in it. A lot to lose over an icon. This changes the category and leaves everything in it where it is. Anything you leave out keeps the value it already has.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **update a category**, and select **Home Assistant Core Integration: Update a category 👻**.
3. Under **Scope**, pick the page the category is on.
4. Under **Category**, type the name of the category to change.
5. Fill in only what should change: a new **Name**, a new **Icon**, or both.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.update_category) opens it in your Home Assistant, ready to run once.

- Renaming a category to a name another category on the same page already has is refused too.

### Add a category to an entity

Puts one or more automations, scripts, scenes, or helpers in a category.

The pages in Home Assistant let you file things by hand. This lets a script or automation do it. The script that sets up your alarm files its helpers under "Security" while it is at it.

There is no **Scope** to pick here: the page follows from what you file. An automation goes into an automation category, a script into a script category, a scene into a scene category, and anything else counts as a helper. Since something sits in one category per page, this replaces the category it was in before.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **add a category to an entity**, and select **Home Assistant Core Integration: Add a category to an entity 👻**.
3. Under **Category**, type the name of the category, like `Lighting`.
4. Under **Entity ID**, pick the automations, scripts, scenes, or helpers to put in it.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.add_category_to_entity) opens it in your Home Assistant, ready to run once.

| **Attribute**              | **Type**                                           | **Required** | **Default / Example**     |
| `category_id`              | :term[string]                                      | Yes          | `Lighting`                |

Every entity, and the category for each of them, is looked up before anything changes. If one of them does not exist, the action stops with an error that names it, and nothing is changed.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

File two automations under Lighting:

```yaml
action: homeassistant.add_category_to_entity
data:
  category_id: Lighting
  entity_id:
    - automation.porch_lights
    - automation.garden_lights
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- The category has to exist on the page of every entity you pick. Filing an automation and a script under `Lighting` in one go needs a Lighting category on the automations page and one on the scripts page.

:::
::

3. Under **Category**, type the name of the category, like `Lighting`.
4. Under **Entity ID**, pick the automations, scripts, scenes, or helpers to take out of it.
