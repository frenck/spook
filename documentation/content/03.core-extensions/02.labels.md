:term[Labels]{to="label"} in :term[Home Assistant] are yours to make up. You use them to build your own way of organizing things, by tagging :term[devices]{to="device"}, :term[entities]{to="entity"}, or :term[areas]{to="area"} with one or more labels. Labels filter the tables in the user interface, and they work as a target for :term[actions]{to="performing actions"} in :term[automations]{to="automation"} and :term[scripts]{to="script"}: "turn off everything labeled Christmas".

In Home Assistant you hand out labels yourself, one by one. Spook adds actions so your automations and scripts can do it too. That makes labels that keep themselves up to date: a "Replace battery" label that lands on a device when its battery runs low, and comes off again once you swapped it. Or labels that are made on the fly, the moment you need one.

## Actions

Spook adds nine actions for labels. You find them wherever you add an action, marked with a 👻. They all belong to the Home Assistant Core Integration, so that is the name in front of them in the list.

Run by hand, these actions need a user that is an administrator. Your automations and scripts can always run them.

### Create a label

Adds a new label to your Home Assistant instance.

Handy when an automation or script needs a label that is not there yet, like a setup script that prepares the labels your other automations use, or a label per guest that arrives.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **create a label**, and select **Home Assistant Core Integration: Create a label 👻**.
3. Give it a **Name** and a **Description**, like `Battery powered` and `Everything that runs on batteries`.
4. If you like, pick an **Icon** and a **Color**.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.create_label) opens it in your Home Assistant, ready to run once.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

A label for everything that runs on batteries:

```yaml
action: homeassistant.create_label
data:
  name: "Battery powered"
  description: "Label to tag all battery powered devices"
  icon: "mdi:battery"
  color: "indigo"
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- A name another label already has is refused. Home Assistant keeps label names unique.
- The action does not respond with the ID of the new label. Since it is made from the name, you can look it up with the `label_id` template, like `{{ label_id('Battery powered') }}`.

### Update a label

Changes the name, description, icon or color of a label that already exists.

Without this, the only way to change a label from an automation was to delete it and create it again. Deleting a label takes it off everything it was on. A lot to lose over a new icon. This changes the label and leaves it where it is.

Anything you leave out keeps the value it already has.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **update a label**, and select **Home Assistant Core Integration: Update a label 👻**.
3. Under **Label ID**, pick the label to change.
4. Fill in only what should change: **Name**, **Description**, **Icon** or **Color**.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.update_label) opens it in your Home Assistant, ready to run once.

| -------------------------- | ----------------------- | ------------ | ------------------------------------------ |
| **Attribute**              | **Type**                | **Required** | **Default / Example**                      |
| `label_id`                 | :term[string]           | Yes          | `battery_powered`                          |
| `name`                     | :term[string]           | No           | `Battery powered`                          |
| `description`              | :term[string] or `null` | No           | `Label to tag all battery powered devices` |
| `icon`                     | :term[string] or `null` | No           | `mdi:battery`                              |
| `color`                    | :term[string] or `null` | No           | `indigo`                                   |

Setting `description`, `icon` or `color` to `null` clears it. Leaving a field out is not the same as giving it an empty string: `description: ""` empties the description, and that counts as a change.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Give a label a better description:

```yaml
action: homeassistant.update_label
data:
  label_id: "battery_powered"
  description: "Label to tag all battery powered devices"
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- You need to give at least one thing to change. A call with only a `label_id` is refused, so a misspelled field gives you an error.
- Renaming a label to a name another label already has is refused too, since Home Assistant keeps label names unique.
- Renaming a label does not change its ID. The ID stays what it was made from, the first name.

:::

### Delete a label

Removes a label from your Home Assistant instance.

For cleaning up after yourself: the label for a guest who went home, or the one a script made for a party that is over. The label comes off every area, device and entity it was on.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **delete a label**, and select **Home Assistant Core Integration: Delete a label 👻**.
3. Under **Label ID**, pick the label to delete.
4. Select **Save**.

### Add a label to an area

Puts one or more labels on one or more areas.

Areas change with the seasons and with how you use them. Label the rooms with heating on as "Heated" in winter, or the guest room as "Occupied" while somebody stays over, and target everything with that label from your other automations.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **add a label to an area**, and select **Home Assistant Core Integration: Add a label to an area 👻**.
3. Under **Label ID**, pick the labels to add.
4. Under **Area ID**, pick the areas that should get them.
5. Select **Save**.

Every label you picked goes on every area you picked. Labels an area already has stay on it.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.add_label_to_area) opens it in your Home Assistant, ready to run once.

4. Under **Area ID**, pick the areas to take them off.

Every label you picked comes off every area you picked. An area that did not have the label is left as it is, and other labels stay on.

### Add a label to an entity

Puts one or more labels on one or more entities.

The same idea as for devices, one level down. Label the sensors that went unavailable, the lights that were left on overnight, or every entity a blueprint touches, and filter the entities table on it later.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **add a label to an entity**, and select **Home Assistant Core Integration: Add a label to an entity 👻**.
3. Under **Label ID**, pick the labels to add.
4. Under **Entity ID**, pick the entities that should get them.
5. Select **Save**.

Every label you picked goes on every entity you picked. Labels an entity already has stay on it.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.add_label_to_entity) opens it in your Home Assistant, ready to run once.
