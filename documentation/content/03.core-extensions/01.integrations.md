:term[Integrations]{to="integration"} in :term[Home Assistant] are the glue between your Home Assistant instance and your devices, services and platforms. You manage them under **Settings** > **Devices & services**, one at a time, by hand.

Spook adds actions for that work, so an automation or script can do it for you: turn an integration off and on again, stop it from asking its devices for updates for a while, or ignore a whole pile of discovered devices in one go.

## Actions

Spook adds five actions for integrations. You find them wherever you add an action, marked with a 👻. They all belong to the Home Assistant Core Integration, so that is the name in front of them in the list.

Run by hand, these actions need a user that is an administrator. Your automations and scripts can always run them.

### Disable an integration

Turns off an integration, one entry of it or all of them at once.

Some integrations you only want running part of the time. The thermostat of the holiday home, only while you are there. The integration of the Christmas lights, from December to January. The cloud service with a paid plan, only when you actually use it. Doing that by hand under **Settings** works, as long as somebody remembers. An automation does.

While an integration is disabled, its devices and entities are disabled with it, exactly like when you disable it in **Settings**. Turning it back on is [Enable an integration](#enable-an-integration).

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **disable an integration**, and select **Home Assistant Core Integration: Disable an integration 👻**.
3. Under **Integration entry**, pick the integration you want to turn off. An integration you set up twice, like two Hue bridges, has two :term[entries]{to="integration entry"}.
4. Or, to turn off every entry of an integration at once, leave that empty and type its domain under **Integration**, like `hue`. The domain is the short technical name of the integration, the one you see in its address in Home Assistant.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.disable_config_entry) opens it in your Home Assistant, ready to run once.

3. Under **Integration entry**, pick the integration you want to turn on.
4. Or, to turn on every entry of an integration at once, leave that empty and type its domain under **Integration**, like `hue`.

### Disable polling for updates

Stops an integration from asking its device or service for updates on a schedule.

Many integrations poll: every so many seconds or minutes, they ask for fresh data. Usually that is what you want. But an integration that talks to a paid API costs money on every poll, also while nobody is home to look at the numbers. With polling off, the integration keeps working. It only stops asking on its own.

Home Assistant has this as a switch in the system options of an integration entry. This action flips that same switch from an automation. Turning it back on is [Enable polling for updates](#enable-polling-for-updates).

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **disable polling**, and select **Home Assistant Core Integration: Disable polling for updates 👻**.
3. Under **Integration entry**, pick the integration that should stop polling.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.disable_polling) opens it in your Home Assistant, ready to run once.

### Ignore all discovered devices & services

Ignores everything Home Assistant discovered and is waiting for you to set up, in one go.

Home Assistant finds things on your network by itself, and lists them under **Settings** > **Devices & services** as discovered. Great when it is the new light you just bought. Less great when it is the neighbors' TV, every Bluetooth gadget that walks past, or the same printer for the third time. You can ignore them one by one. This ignores them all at once.

You can limit it to one integration. For example, run it every night for the `bluetooth` integration only, and keep the rest of the discoveries for you to look at.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **ignore all**, and select **Home Assistant Core Integration: Ignore all currently discovered devices 👻**.
3. To ignore only what one integration discovered, type its domain under **Integration domain**, like `bluetooth`. Leave it empty to ignore everything.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.ignore_all_discovered) opens it in your Home Assistant, ready to run once.
