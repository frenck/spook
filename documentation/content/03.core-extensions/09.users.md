A user in :term[Home Assistant] is an account that can log in and control your home. You manage them in the UI, under **Settings** > **People**.

Spook adds :term[actions]{to="action"} to disable a user account and enable it again from an :term[automation] or :term[script].

## Actions

Spook adds two actions for users. You find them wherever you add an action, marked with a 👻. They change who can get in: calling one by hand takes an administrator, while automations and scripts run them as usual.

### Disable a user

Disables one or more user accounts, so they can no longer log in.

The same as switching a user off in the UI, but from an automation. The house sitter gets an account for the two weeks you are away, and it closes by itself the day you are back. The contractor who set up the solar panels keeps access until the job is done. [Enable a user](#enable-a-user) opens it again.

**How to use it**

1. Open the automation or script that should disable the user, and select **Add action**.
2. Search for **disable a user**, and select **Home Assistant Core Integration: Disable a user 👻**.
3. Under **User ID**, type the ID of the user. See _Finding a user ID_ below.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.disable_user) opens it in your Home Assistant, ready to run once.

Disabling a user also logs them out everywhere they are logged in. Their long-lived access tokens stop working too, and do not come back when the user is enabled again.

:::

:::accordion-item{label="Finding a user ID" icon="i-mdi-lightbulb-outline"}

Not sure what the `user_id` of a user is? In the Home Assistant UI, go to **Settings** > **People** and open the **Users** tab. That tab shows when advanced mode is on in your user profile. Select the user, and the dialog shows their ID.

Or go to **Settings** > **Tools** > **Template**, and use this template to list the user ID of every person:

```yaml
{% for state in states.person %}
Name: {{ state.name }}
ID: {{ state.attributes.user_id }}
------------------
{% endfor %}
```

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Disable one user:

```yaml
action: homeassistant.disable_user
data:
  user_id: "bf1f3b59c7a842c8a9de3e1c12345678"
```

More than one user at once, as a list:

```yaml
action: homeassistant.disable_user
data:
  user_id:
    - "bf1f3b59c7a842c8a9de3e1c12345678"
    - "a3c9d12e4f5b678901234567890abcde"
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- The owner of Home Assistant cannot be disabled. Home Assistant refuses it.
- Users Home Assistant made for itself, like the one for the Supervisor, are refused as well.

:::
::

### Enable a user

Enables one or more disabled user accounts, so they can log in again.

The way back from [Disable a user](#disable-a-user): the house sitter is back for the summer, and their account opens again the day they arrive. They log in once more, since disabling logged them out.

**How to use it**

1. Open the automation or script that should enable the user, and select **Add action**.
2. Search for **enable a user**, and select **Home Assistant Core Integration: Enable a user 👻**.
3. Under **User ID**, type the ID of the user. See _Finding a user ID_ below.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.enable_user) opens it in your Home Assistant, ready to run once.
