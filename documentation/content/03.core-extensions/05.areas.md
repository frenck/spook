:term[Areas]{to="area"} in :term[Home Assistant] group your :term[devices]{to="device"} and :term[entities]{to="entity"} the way your house does: the living room, the kitchen, the garden. Target an area, and you reach everything in it.

You set up areas in the UI, under **Settings** > **Areas, labels & zones**. Spook adds :term[actions]{to="action"} that do the same from an :term[automation] or :term[script]: create an area, change it, delete it, and move devices and entities in and out of it. Handy when a script sets up a fresh installation, or when a device moves around the house.

Spook also tells you about an area that has nothing in it at all. That one is on the [Home Assistant page](/homeassistant#empty-areas).

## Actions

Spook adds ten actions for areas. You find them wherever you add an action, marked with a 👻. They change your setup: calling one by hand takes an administrator, while automations and scripts run them as usual.

### Create an area

Adds a new area to Home Assistant.

The UI is the place to set up the rooms you have. This is for the areas a script or automation should make: setting up a new installation from a script, or creating the areas another system already knows about.

**How to use it**

1. Open the automation or script that should create the area, and select **Add action**.
2. Search for **create an area**, and select **Home Assistant Core Integration: Create an area 👻**.
3. Fill in **Name**, like `Living room`.
4. If you like, also set **Icon**.
5. If you like, add **Aliases**: other names for the area, like `Lounge`, that voice assistants understand too. Write them as a list, one per line starting with `- `.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.create_area) opens it in your Home Assistant, ready to run once.

### Update an area

Changes an area that already exists: its name, aliases, floor, icon, picture, labels, or its temperature and humidity sensors.

Deleting an area and creating it again takes every device and entity out of it. A lot to lose over an icon. This changes only what you give it, and keeps everything else as it was. So you can move an area to another floor without touching its name, or point it at a new temperature sensor after you replaced the old one.

**How to use it**

1. Open the automation or script that should change the area, and select **Add action**.
2. Search for **update an area**, and select **Home Assistant Core Integration: Update an area 👻**.
3. Pick the area under **Area ID**.
4. Turn on only the fields you want to change, like **Name**, **Floor ID**, **Icon**, **Labels** or **Temperature sensor**, and fill them in. Fields you leave off keep their value.
5. Select **Save**.

The **Aliases** and **Labels** you give replace the ones the area has. To add or remove a single alias, use [Add an alias to an area](#add-an-alias-to-an-area) or [Remove an alias from an area](#remove-an-alias-from-an-area) instead.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.update_area) opens it in your Home Assistant, ready to run once.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Move the living room to the ground floor, and give it a sofa for an icon:

```yaml
action: homeassistant.update_area
data:
  area_id: "living_room"
  floor_id: "ground_floor"
  icon: "mdi:sofa"
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- You need to give at least one thing to change. A call with only an `area_id` is refused, so a misspelled field gives you an error.
- The floor, labels and sensors you give have to exist, and the sensors have to measure temperature and humidity. Everything is checked before anything is written, so a refused call changes nothing.
- Renaming an area to a name another area already has is refused, since Home Assistant keeps area names unique. A different spelling of its own name, like other upper and lower case, is fine.

:::

### Delete an area

Removes an area from Home Assistant.

The other half of [Create an area](#create-an-area): an area a script made for a while can go again the same way. The devices and entities in it stay. They just are no longer in an area.

**How to use it**

1. Open the automation or script that should delete the area, and select **Add action**.
2. Search for **delete an area**, and select **Home Assistant Core Integration: Delete an area 👻**.
3. Pick the area under **Area ID**.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.delete_area) opens it in your Home Assistant, ready to run once. Careful: that run deletes the area for real.

Adding one from an automation lets you make a name available only when it makes sense: "the guest room" while the guests are there, and gone again after with [Remove an alias from an area](#remove-an-alias-from-an-area).

**How to use it**

3. Pick the area under **Area ID**.
4. Under **Alias**, write the name to add. For more than one, write them as a list, one per line starting with `- `.
5. Select **Save**.

### Add a device to an area

Puts one or more devices in an area. The other devices in that area stay where they are.

A device is in one area at most, so a device that was in another area moves. Think of the speaker you carry from the kitchen to the garden, or the space heater that follows you around the house in winter: tell Home Assistant where it is now, and "turn off everything in the kitchen" no longer reaches it.

**How to use it**

1. Open the automation or script that should move the device, and select **Add action**.
2. Search for **add a device to an area**, and select **Home Assistant Core Integration: Add a device to an area 👻**.
3. Pick the area under **Area ID**.
4. Pick one or more devices under **Device ID**.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.add_device_to_area) opens it in your Home Assistant, ready to run once.

### Add an entity to an area

Puts one or more entities in an area. The other entities in that area stay where they are.

An entity normally sits in the area of its device. This puts it somewhere else, and that wins over the area of its device. Handy for the smart plug in the kitchen that powers the lamp in the hallway: the plug is a kitchen device, but the light it switches belongs in the hallway.

**How to use it**

1. Open the automation or script that should move the entity, and select **Add action**.
2. Search for **add an entity to an area**, and select **Home Assistant Core Integration: Add an entity to an area 👻**.
3. Pick the area under **Area ID**.
4. Pick one or more entities under **Entity ID**.
