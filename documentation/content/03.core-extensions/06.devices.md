A :term[device] in :term[Home Assistant] is usually a physical thing in your home, like a thermostat or a smart plug. It can also be a web service, like one that provides weather information. A device groups the entities that belong to it.

You manage devices in the UI, under **Settings** > **Devices & services** > **Devices**. Spook adds :term[actions]{to="action"} that do some of that from an :term[automation] or :term[script]: disable a device, enable it again, and change its name, area or labels.

## Actions

Spook adds three actions for devices. You find them wherever you add an action, marked with a 👻. They change your setup: calling one by hand takes an administrator, while automations and scripts run them as usual.

### Disable a device

Disables one or more devices, the same as the **Disable** button on the device page.

A disabled device takes its entities with it: they are disabled too, and drop out of your dashboards and automations. Think of the Christmas lights that are in the attic for eleven months a year, or the summer house you only visit in July. Disable their devices when they are packed away, and they stop filling your logs and dashboards with unavailable entities. [Enable a device](#enable-a-device) brings them back.

**How to use it**

1. Open the automation or script that should disable the device, and select **Add action**.
2. Search for **disable a device**, and select **Home Assistant Core Integration: Disable a device 👻**.
3. Pick one or more devices under **Device**.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.disable_device) opens it in your Home Assistant, ready to run once.

Disable one device:

```yaml
action: homeassistant.disable_device
data:
  device_id: "dc23e666e6100f184e642a0ac345d3eb"
```

More than one device at once, as a list:

```yaml
action: homeassistant.disable_device
data:
  device_id:
    - "dc23e666e6100f184e642a0ac345d3eb"
    - "df98a97c9341a0f184e642a0ac345d3b"
```

### Enable a device

Enables one or more disabled devices again.

The way back from [Disable a device](#disable-a-device): the Christmas lights come down from the attic, and their device and entities come back to life.

**How to use it**

1. Open the automation or script that should enable the device, and select **Add action**.
2. Search for **enable a device**, and select **Home Assistant Core Integration: Enable a device 👻**.
3. Under **Device ID**, type the ID of the device. The usual device picker does not show disabled devices, which is why this one asks for the ID. See _Finding a device ID_ below.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.enable_device) opens it in your Home Assistant, ready to run once.

### Update a device

Changes the name, area or labels of a device, or disables or enables it.

These are the things you can change about a device in the UI, now from an automation. A sensor that moved from the bedroom to the nursery gets a new name and a new area in one step. Everything you leave out keeps the value it already has.

**How to use it**

1. Open the automation or script that should change the device, and select **Add action**.
2. Search for **update a device**, and select **Home Assistant Core Integration: Update a device 👻**.
3. Pick the device under **Device ID**.
4. Turn on only the fields you want to change, like **Name**, **Area ID**, **Labels** or **Disabled by**, and fill them in. Fields you leave off keep their value.
5. Select **Save**.

The **Labels** you give replace the ones the device has. Setting **Disabled by** to **User** disables the device, the same as [Disable a device](#disable-a-device).

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.update_device) opens it in your Home Assistant, ready to run once.

| **Action data parameters** |                                                    |              |                                    |
| -------------------------- | -------------------------------------------------- | ------------ | ---------------------------------- |
| **Attribute**              | **Type**                                           | **Required** | **Default / Example**              |
| `device_id`                | :term[string]                                      | Yes          | `dc23e666e6100f184e642a0ac345d3eb` |
| `name_by_user`             | :term[string] or `null`                            | No           | `Living room speaker`              |
| `area_id`                  | :term[string] or `null`                            | No           | `living_room`                      |
| `labels`                   | :term[string] \| :term[list of strings]{to="list"} | No           | `["battery_powered"]`              |
| `disabled_by`              | `user` or `null`                                   | No           | `user`                             |

Anything you leave out keeps the value it already has. Setting `name_by_user` to `null` gives the device back the name its integration gave it, and setting `area_id` to `null` takes it out of its area. The `labels` you give replace the ones the device has, and an empty list removes them all. Setting `disabled_by` to `user` disables the device, and setting it to `null` enables it again, the same way the disable and enable device actions above do.

Only what you can change on a device in the UI is offered. Everything else, like its manufacturer or model, belongs to the integration that made the device. The integration would write its own values back the next time it sets up.

:::

:::accordion-item{label="Example actions in YAML" icon="i-mdi-code-braces"}

Rename a speaker, and move it to the living room:

```yaml
action: homeassistant.update_device
data:
  device_id: "dc23e666e6100f184e642a0ac345d3eb"
  name_by_user: "Living room speaker"
  area_id: "living_room"
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- You need to give at least one thing to change. A call with only a `device_id` is refused, so a misspelled field gives you an error.
- The area and labels you give have to exist. They are checked before anything is written, so a refused call changes nothing.
- The device picker does not show disabled devices. To change one, give its ID in YAML mode.

:::
