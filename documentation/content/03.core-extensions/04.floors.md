:term[Floors]{to="floor"} in :term[Home Assistant] group your :term[areas]{to="area"} the way your house does: the ground floor, the first floor, the attic. They give a better overview of your home, and you can target :term[actions]{to="performing actions"} at a whole floor at once, like turning off all the lights upstairs.

You set up floors in the UI, under **Settings** > **Areas, labels & zones**. Spook adds :term[actions]{to="action"} that do the same from an :term[automation] or :term[script]: create a floor, change it, delete it, and move areas on and off it. Handy when a script sets up a fresh installation, or when floors should follow another system.

Spook also tells you about a floor that has no areas on it at all. That one is on the [Home Assistant page](/homeassistant#empty-floors).

## Actions

Spook adds eight actions for floors. You find them wherever you add an action, marked with a 👻. They change your setup: calling one by hand takes an administrator, while automations and scripts run them as usual.

### Create a floor

Adds a new floor to Home Assistant.

The UI is the place to set up the floors you have. This is for the floors a script or automation should make: setting up a new installation from a script, or building a floor plan that another system already knows about.

**How to use it**

1. Open the automation or script that should create the floor, and select **Add action**.
2. Search for **create a floor**, and select **Home Assistant Core Integration: Create a floor 👻**.
3. Fill in **Name**, like `First floor`.
4. If you like, also set **Icon** and **Level**. The level is the number of the floor, `0` for the ground floor.
5. If you like, add **Aliases**: other names for the floor, like `Downstairs`, that Assist understands too. Write them as a list, one per line starting with `- `.
6. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.create_floor) opens it in your Home Assistant, ready to run once.

### Update a floor

Changes the name, aliases, icon or level of a floor that already exists.

Deleting a floor and creating it again takes every area off it. A lot to lose over an icon. This changes only what you give it, and keeps everything else as it was. So you can change the icon without touching the name or the level.

**How to use it**

1. Open the automation or script that should change the floor, and select **Add action**.
2. Search for **update a floor**, and select **Home Assistant Core Integration: Update a floor 👻**.
3. Pick the floor under **Floor ID**.
4. Turn on only the fields you want to change, like **Name**, **Aliases**, **Icon** or **Level**, and fill them in. Fields you leave off keep their value.
5. Select **Save**.

The **Aliases** you give replace the ones the floor has. To add or remove a single alias, use [Add an alias to a floor](#add-an-alias-to-a-floor) or [Remove an alias from a floor](#remove-an-alias-from-a-floor) instead.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.update_floor) opens it in your Home Assistant, ready to run once.

```yaml
  level: 0
```

:::
:::accordion-item{label="Known limitations" icon="i-mdi-alert-outline"}

- You need to give at least one thing to change. A call with only a `floor_id` is refused, so a misspelled field gives you an error.
- Renaming a floor to a name another floor already has is refused, since Home Assistant keeps floor names unique. A different spelling of its own name, like other upper and lower case, is fine.

1. Open the automation or script that should delete the floor, and select **Add action**.
2. Search for **delete a floor**, and select **Home Assistant Core Integration: Delete a floor 👻**.
3. Pick the floor under **Floor ID**.

### Add an alias to a floor

Adds one or more aliases to a floor, and keeps the ones it already has.

Aliases are the other names a floor goes by, and voice assistants listen for them. Adding one from an automation lets you make a name available only when it makes sense: "the party floor" during the party, and gone again the next morning with [Remove an alias from a floor](#remove-an-alias-from-a-floor).

3. Pick the floor under **Floor ID**.
4. Under **Alias**, write the name to add. For more than one, write them as a list, one per line starting with `- `.

The same, using the names of the floor and the area instead of their IDs:

```yaml
action: homeassistant.add_area_to_floor
data:
  floor_id: "{{ floor_id('First floor') }}"
  area_id: "{{ area_id('Living room') }}"
```

More than one area at once, as a list:

```yaml
action: homeassistant.add_area_to_floor
data:
  floor_id: "first_floor"
  area_id:
    - "living_room"
    - "kitchen"
```

### Remove an area from a floor

Takes one or more areas off the floor they are on. The other areas on that floor stay where they are.

The area itself stays, with everything in it. It just no longer sits on a floor. You don't say which floor: an area is on one floor at most, so Spook knows.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **remove an area from a floor**, and select **Home Assistant Core Integration: Remove an area from a floor 👻**.
3. Pick one or more areas under **Area ID**.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.remove_area_from_floor) opens it in your Home Assistant, ready to run once.
