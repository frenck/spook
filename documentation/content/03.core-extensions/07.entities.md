:term[Entities]{to="entity"} are the building blocks of :term[Home Assistant]: every light, sensor, switch and button you see is one. You change their settings in the UI, in the settings dialog of each entity.

Spook adds :term[actions]{to="action"} that change those same settings from an :term[automation] or :term[script]: disable or hide an entity, give it a new name, icon or aliases, decide which voice assistants may see it, and clean up the entities nothing claims anymore.

## Actions

Spook adds fourteen actions for entities. You find them wherever you add an action, marked with a 👻. Most of them change your setup: calling one of those by hand takes an administrator, while automations and scripts run them as usual.

### Disable an entity

Disables one or more entities, the same as turning off **Enabled** in the entity's settings.

A disabled entity is gone from Home Assistant until you enable it again: no state, no new history, nothing in your dashboards. Handy for the sensors of a device that is packed away for the season, or a noisy entity you only need once in a while. [Enable an entity](#enable-an-entity) brings it back.

**How to use it**

1. Open the automation or script that should disable the entity, and select **Add action**.
2. Search for **disable an entity**, and select **Home Assistant Core Integration: Disable an entity 👻**.
3. Pick one or more entities under **Entity**.
4. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.disable_entity) opens it in your Home Assistant, ready to run once.

### Hide an entity

A hidden entity keeps working. It just stays out of sight. It does not show up on dashboards that Home Assistant builds for you, and voice assistants like Google Assistant or Alexa don't see it by default. You can still expose it to them on purpose, in the voice assistant settings. Useful for the helper entities and technical sensors you need, but never want to look at.

### Expose an entity to assistants

Lets one or more voice assistants see and control one or more entities.

Home Assistant keeps a separate list per assistant of what it may see. This is the same setting you find under **Settings** > **Voice assistants** > **Expose**, applied to as many entities as you like at once. Expose the guest room lights to Assist when guests arrive, or a whole batch of new entities to Alexa without ticking them one by one.

**How to use it**

1. Open the automation or script that should do this, and select **Add action**.
2. Search for **expose an entity**, and select **Home Assistant Core Integration: Expose an entity to assistants 👻**.
3. Pick one or more entities under **Entity**.
4. Under **Assistants**, pick **Alexa**, **Google Assistant**, **Assist**, or any mix of them.
5. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.expose_entity) opens it in your Home Assistant, ready to run once.

### Update an entity's ID

**How to use it**

3. Pick the entity under **Entity**.
4. Fill in **New Entity ID**, like `light.dining_room`.

### Delete all orphaned entities

Deletes every orphaned entity in one go.

An orphaned entity is one no integration claims anymore. Remove an integration, or replace a device, and its entities can stay behind in the entity list, marked as no longer provided. Deleting them one by one gets old fast. This deletes all of them at once.

::warning
Home Assistant marks an entity orphaned when its integration has not set it up since the last start. An integration that is offline, or failed to start, leaves its entities looking orphaned too. Running this action deletes those entities as well.

::

**How to use it**

1. Make sure every integration you care about is up and running. Check **Settings** > **Devices & services** for any that failed to load.
2. Open the script that should do the cleanup, and select **Add action**.
3. Search for **orphaned entities**, and select **Home Assistant Core Integration: Delete all orphaned entities 👻**.
4. There is nothing to fill in. Select **Save**.

Just want to see it work? [Try this action](https://my.home-assistant.io/redirect/developer_call_service/?service=homeassistant.delete_all_orphaned_entities) opens it in your Home Assistant, ready to run once. Careful: that run deletes them for real.

### List all orphaned database entities

Lists the entities your database still holds history for, but that no longer exist in Home Assistant.

Remove an integration, or disable an entity, and its history stays in the database. That history takes up space and does nothing for you. This finds those entities, so you can decide what to purge. It only lists, it deletes nothing.

**How to use it**

1. Open the script that should use the list, and select **Add action**.
2. Search for **orphaned database entities**, and select **Home Assistant Core Integration: List all orphaned database entities 👻**.
3. Under **Response variable**, give the list a name, like `orphaned`. The steps after this one can use it.
4. Select **Save**.

```yaml
alias: Delete orphaned database entities
sequence:
  - action: homeassistant.list_orphaned_database_entities

    target:
      entity_id: |
        {{ orphaned.entities }}
    data:
      keep_days: 0
mode: single
```
