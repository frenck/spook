So, you found a security vulnerability in Spook? Please disclose it to us _responsibly_, by [reporting a vulnerability using GitHub's Security Advisory](https://github.com/frenck/spook/security/advisories/new).

**Do _not_ open a public issue for a security vulnerability!**

For the sake of everyone using Spook, please 🙏 do not make a vulnerability public without telling us first, and giving us at least 90 days to release a fixed version. We do our best to respond to your report within 7 days, and to keep you posted while we work on it. But understand that Spook, like many open source projects, is mostly a volunteer project, without full-time people on it. We may not respond as quickly as you would like.

Going to write about Spook's security? Please get in touch first, so we can make sure all claims are correct.

## Supported versions

We only accept reports against the latest stable, official version of Spook, or anything newer that is in development. You find the latest version [here](https://github.com/frenck/spook/releases/latest).

We do not accept reports against forks of Spook.

## Non-qualifying vulnerabilities

We do not accept reports of these kinds:

- Reports from automated tools or scanners.
- Theoretical attacks without proof of exploitability.
- Attacks that are the result of a third-party application or library (these should instead be reported to the library maintainers).
- Social engineering.
- Attacks involving physical access to a user's device, or a device or network that is already seriously compromised (like man-in-the-middle).
- Attacks that require the user to install a malicious other :term[integration] or add-on.
- Attacks that the user can only perform on themselves.

## Severity scoring

If you know [CVSS3.1](https://www.first.org/cvss/v3.1/specification-document), please add the score of the vulnerability to your report, as a vector string. There is a calculator [here](https://www.first.org/cvss/calculator/3.1). Not sure how to score it? Say so in your report, and we will look into it.

If you do add a score, get to know CVSS first (we strongly recommend reading the [Specification](https://www.first.org/cvss/v3.1/specification-document) and the [Scoring Guide](https://www.first.org/cvss/v3.1/user-guide#Scoring-Guide)), as we do not accept reports that use it incorrectly.

## Public disclosure & CVE assignment

For valid vulnerabilities, we publish a GitHub Security Advisory, and request a CVE through it, when all of these hold:

- The vulnerability is in Spook itself, not in a third-party library.
- The vulnerability is not already known to us.
- The vulnerability is not already known to the public.
- The vulnerability has a severity of Medium or higher.

## Bounties

As a crowd-funded community project, Spook cannot offer bounties for security vulnerabilities. If you like, we credit you as the one who found it in the release notes.
