There are many ways to help with Spook, and most of them need no code at all.

## Reporting issues and submitting feature requests

Found a bug? Report it on the [Spook issue tracker on GitHub](https://github.com/frenck/spook/issues). A pull request with a fix is even more awesome! 🤩

Got an idea? Share it on the [Spook discussion forum on GitHub](https://github.com/frenck/spook/discussions), or build it yourself and open a pull request! 🤩

## Translating Spook

Spook speaks quite a few languages, but our beloved ghost is not that good at all of them. So, it needs your help translating Spook into yours!

Translating needs no coding skills at all. You translate the sentences [straight from your browser](https://hosted.weblate.org/engage/spook/)!

A sentence that is not translated yet falls back to English. If you see English text, that is what happened.

[![Translation status](https://hosted.weblate.org/widgets/spook/-/integration/287x66-black.png)](https://hosted.weblate.org/engage/spook/)

🌎 [Start helping to translate Spook into your language!](https://hosted.weblate.org/engage/spook/)

Spook supports all languages that Home Assistant supports. Missing yours? Add it, or [let us know in the discussion forums](https://github.com/frenck/spook/discussions).

### Translating the website

This website is a different story. Its pages in other languages are machine-translated from the English ones, and regenerated whenever the English text changes.

Spotted something wrong or odd on a translated page? [Report the translation problem](https://github.com/frenck/spook/issues/new?template=translation.yml). A report improves the instructions the translator works from, so the fix sticks, and similar sentences get better too.

Pull requests that edit a translated page are not accepted. Nothing personal: the next run would overwrite your work, and a check on the pull request tells you so. Want to improve a translation structurally? The style guides and glossaries live in the `documentation/translations/corpus` folder of the GitHub repository, and those are edited by hand.

## Improving the documentation

Spook is already scary enough for many, so the documentation should be as good as possible.

The documentation is built with [Nuxt Content](https://content.nuxt.com), and every page is a [Markdown](https://www.markdownguide.org/) file, with a few components on top, like the cards and the collapsible sections you see around the site. Found a typo? Every page lives in the `documentation/content` folder of the GitHub repository, so a small fix is a small pull request:

<https://github.com/frenck/spook/tree/main/documentation>

To run the documentation locally, clone the Spook repository, and from the `documentation` folder, run:

```bash
npm ci
npm run dev
```

This starts a local web server on `http://localhost:3000`, which updates by itself when you change the documentation.

## Developing Spook

You can find the source code of Spook on GitHub: <https://github.com/frenck/spook>

The repository comes with a devcontainer. Open it in Visual Studio Code, reopen it in the container, and it installs what you need, for Spook and the documentation both. Prefer your own setup? Spook uses [uv](https://docs.astral.sh/uv/): run `uv sync` in the repository, and `uv run pytest` runs the tests.

To try Spook in a real Home Assistant:

- As Spook is a custom integration, it can be developed in a regular Home Assistant development environment, as described [here](https://developers.home-assistant.io/docs/development_environment). Place the `spook` folder from the `custom_components` folder in the `custom_components` folder of your development environment config folder.
- If you develop Home Assistant in a virtual environment, you could clone Spook's repository in any folder, and symlink the `spook` folder from the `custom_components` folder into the `custom_components` folder of your development environment config folder.

### Opening a pull request

Want to open a pull request? Go ahead! 🤩

Test your changes before you open it, so you know they work as expected. Say what the change does and why in the pull request, so nobody has to figure that out from the code.

And update the documentation where needed. I know this isn't the most fun part, but it is how people find out about the awesome changes you made.
